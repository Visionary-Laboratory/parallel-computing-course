# 矩阵性能实验（现第一讲） · 本机会话实验记录

2026-09-11 本会话实际执行，CPU 为 Apple M5，arm64，macOS 26.6.2。编译器为 Apple LLVM 21.0.0 (clang-2100.1.1.101)。这些数据是 CPU 代码对照，不是 GPU 性能，不与课堂假设的 GPU 屋顶相混用。

```bash
c++ -std=c++17 -O3 -ffp-contract=off gemm-memory.cpp -o gemm-memory
./gemm-memory --self-test
./gemm-memory 128 5
./gemm-memory 256 5
./gemm-memory 512 5
```

同一源码 SHA-256：`3a53230b023edc5b6484ed6629e2983daf120e373a48d06db2a0764f586b8a0c`。

## 计时与正确性

- FP32 输入与输出、C=AB；三个数据数组独立，连续行优先。确定性的正负输入，非真实模型权重分布。
- 无显式多线程和手写 SIMD；编译器仍可自动向量化。统一 O3，禁用 FMA contraction，未开启 fast-math。
- 分配、输入生成、FP64 参考、预热、正确性验证和 checksum 在计时之外。i-k-j 与分块中的 C 清零在计时之内；i-j-k 以局部累加器覆盖输出。
- 每个版本预热一次，随后每版测 5 次，轮换各版本的执行次序；CSV 是程序直接报告的 min/median/max 汇总，不是逐次原始样本列表。
- 每次计算都完整核对结果，预设判据为 abs_error <= 1e-4 + 2e-4 * abs(reference)，并报告最大绝对误差。该容差面向本例的受控输入，不是所有数据的通用精度保证。
- 自检通过：矩形、tile 尾部、正负输入、C 重复覆盖、K=0、已知结果。

## 解释范围

| --- | --- | --- | --- | --- | --- |

| 256 | 9.366 ms | 0.985 ms | 1.874 ms | 1.670 ms | 1.203 ms |
| 512 | 77.984 ms | 8.566 ms | 15.450 ms | 13.474 ms | 11.747 ms |


输入重复使用，缓存并非严格冷启动。未绑核、未固定频率、未控制温度与其他系统负载，单次会话的结果需要结合 min/max 理解。没有采集 DRAM 流量或缓存计数器，不能从这些时间单独证明 DRAM 字节数减少。

这组数据里 i-k-j 优于所实现的三种分块；分块相对 i-j-k 有收益，不代表比所有合理基线都好。可进一步检查编译器报告、不同矩阵规模与缓存行为；不要挑选最有利的一列代替完整报告。

## 编译器报告补充

同一编译器、源码和优化参数另加诊断选项后，i-j-k、i-k-j 和分块内层三个循环均报告 vectorized（width 4, interleaved count 4）。[报告节选](compiler-vectorization.txt)保留了原行号。因此不能用“只有 i-k-j 被向量化”解释这张表；向量化报告也不等于三种访问方式有相同的指令效率。诊断编译不替换前面计时结果。
