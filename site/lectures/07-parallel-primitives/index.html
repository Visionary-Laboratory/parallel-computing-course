并行算子中的结果合并与地址分配

第五讲让线程独立写输出；第六讲用 shared 交换和复用输入。现在，多个线程要共同决定一个输出或一组输出地址。

本讲模式PyTorch 中的相关操作要理解的并行问题
Reduce：多项合成一项sum、mean、amax线程之间怎样合并结果
Scan：每项的累计量cumsumblock 之间怎样补齐前缀
Stable compaction：稳定筛选x[mask]、masked_select怎样给保留项分配位置
Histogram：各桶计数bincount多个输入怎样更新同一桶

第三讲的算法思想在这里变成可编译的程序：局部计算 → 合并结果 → 建立下一阶段所需的位置或统计量。

这些函数体现相同的并行任务；PyTorch 会按输入与设备选择实现，不一定采用本讲的 kernel 划分。

PyTorch 中的归约与维度

python
import torch
x = torch.tensor([[1., 2., 3.], [4., 5., 6.]], device="cuda")
print(torch.sum(x).item())             # 21.0：全部元素合成一个数
print(torch.sum(x, dim=0).tolist())     # [5.0, 7.0, 9.0]：每列一个和
print(torch.sum(x, dim=1).tolist())     # [6.0, 15.0]：每行一个和

dim 指定被合并的维度：dim=1 把每行的三列合起来，dim=0 把每列的两行合起来；keepdim=True 则保留长度为 1 的维度。

训练中的 loss.mean() 把多个损失归约为平均值，torch.amax(x, dim=1) 把每行归约为最大值。操作变了，多个线程合并结果的问题仍然存在。

线程局部累加与 grid-stride 分工

cpp
float local = 0.0f;
size_t stride = size_t(blockDim.x) * gridDim.x;
for (size_t i = size_t(blockIdx.x)*blockDim.x + threadIdx.x;
     i < n; i += stride)
    local += x[i];

x 是输入，n 是长度；i 是当前线程读取的下标，stride 是整个 grid 的线程数，local 是当前线程自己的部分和。size_t 是用于长度与下标的整数类型。

沿用图中的 N=16、2个 block、每块4线程：stride=8。block 0 的线程0从 i=0 开始，再读 i=8，得到1+9=10；下次 i=16 已不满足 i<n，循环结束。

block 0 的四个 local 为 10、12、14、16，合为52；block 1 合为84；最终52+84=136。实际程序每块256线程，分工公式相同。

09 · 主题链接

共享内存归约与逐层同步

先放大图中的 block 0：四个线程把 local 写入 s = [10,12,14,16]；间隔 2 时，前两项变为 [24,28]；间隔 1 时，再合成 52。

cpp
// reduce_shared：固定256线程，local已用grid-stride累加
__shared__ float s[256];
unsigned t = threadIdx.x;
s[t] = local;
__syncthreads();
for (unsigned d = 128; d > 0; d >>= 1) {
    if (t < d) s[t] += s[t + d];
    __syncthreads();
}
if (t == 0) partial[blockIdx.x] = s[0];

d >>= 1 每次把正整数 d 除以2：128、64…1。只让前 d 个线程更新节点，但所有线程仍经过每一道 barrier。

没有分到输入的线程令 local=0：加 0 不改变总和，又能让所有线程一起完成同步与归约。 最终仅线程0写出部分和；__syncthreads() 只保证阶段顺序，不合并数据。

10 · 主题链接

共享内存归约的完整 kernel

把前两页的“线程累加”和“块内合并”接起来。x、partial 都是设备指针，n 是输入长度；启动时每个 block 固定 256 线程。

cpp
__global__ void reduce_shared(const float* x, float* partial, size_t n) {
    __shared__ float s[256];
    unsigned t = threadIdx.x;
    float local = 0;                      // ① 每线程先累加自己的输入
    for (size_t i = size_t(blockIdx.x)*256+t; i < n; i += size_t(gridDim.x)*256)
        local += x[i];
    s[t] = local;                         // ② 交给本块shared数组
    __syncthreads();
    for (unsigned d = 128; d > 0; d >>= 1) {
        if (t < d) s[t] += s[t+d];
        __syncthreads();
    }
    if (t == 0) partial[blockIdx.x] = s[0]; // ③ 每块写出一个部分和
}

每线程局部累加 → 写 shared → 逐层合并 → 线程0写本块部分和。 partial 的长度等于 grid 的 block 数；这里还不是全局最终和。

Warp 内归约：沿用逐层折半求和

继续上一页的伙伴取值方式，用8个lane的缩小模型手算，初值为1…8。每轮用shuffle取得编号更大的伙伴值：offset=4时，lane 0 算1+5、lane 1 算2+6。

text
offset 4 后，lane 0…3：6  8 10 12
offset 2 后，lane 0…1：16 20
offset 1 后，lane 0：36

每轮待合并的有效结果数从8减为4、2、1，最终 lane 0 持有总和36；其他lane不保证也有完整和。实际32个lane依次取距离 16、8、4、2、1 的伙伴。接下来先看硬件如何传值，再写成循环。

13 · 主题链接

Warp shuffle 的硬件数据路径

shuffle 由 GPU 的 SHFL 指令支持。执行时，SM 内的数据通路按源lane编号选出寄存器值，复制到接收线程的目标寄存器：

  • 按编号选值： 可以把这段电路理解成“交换网络”；每个接收lane按本轮规则取得一个源lane的值。
  • 交换走寄存器通路： 这一步无需先写shared再读回，也不需要经过L1、L2或显存。
  • 交换之后再运算： lane 0 先得到 peer=5，再做 v += peer；shuffle本身不执行加法。它只在同一warp内传值。
14 · 主题链接

Warp shuffle 的数据交换

把前面的32项归约写成函数。v 是当前线程的数，peer 是这一轮取到的伙伴值；先取值，再相加：

cpp
__device__ float warp_sum(float v) {
    for (int d = 16; d > 0; d >>= 1) {
        float peer = __shfl_down_sync(0xffffffffu, v, d);
        v += peer;
    }
    return v; // 只有lane 0作为完整warp和使用
}
  • __device__：由设备代码调用的函数；不是另一次 kernel launch。
  • 0xffffffffu：0x 表示十六进制，每个 f 是二进制 1111；8个 f 合计32个1。u 表示无符号整数，本例用全1掩码让32条lane都参加。
  • __shfl_down_sync(mask, v, d)：取同warp中“本lane编号+d”的值；编号超出warp范围时返回自己的原值。最终只用lane 0的完整和。

这是 common.cuh 中 warp_reduce<false> 的求和版本；尖括号中的 false 是编译时选择参数，后面解释完整模板。_sync 协调交换的参与线程，不等于shared/global内存屏障。

Warp 归约的参与范围

cpp
// 固定启动完整的32线程warp，输入不足时补0。
float v = i < n ? x[i] : 0.0f;
float w = warp_sum(v); // 所有lane调用；只使用lane 0的完整和

没有输入，不等于不参加归约。 例如最后只有5个数：lane 0…4带真实值，其余27条lane带0，仍沿同一棵32项树合并。

把 0xffffffffu 展开来看（0x 是十六进制前缀，u 是无符号后缀）：

text
十六进制： f    f    f    f    f    f    f    f
二进制： 1111 1111 1111 1111 1111 1111 1111 1111

最右侧bit 0对应lane 0，最左侧bit 31对应lane 31；位为1表示该lane参与。 掩码决定“谁参加”，伙伴编号由shuffle的模式和距离决定。

输入不足时补0，尾部线程仍参加。本讲每block固定256线程，得到8个warp部分和，接下来再合成一个block结果。

16 · 主题链接

用模板选择求和或最大值

对 [1,2,3,4] 归约，求和得到 10，求最大值得到 4。逐层合并的流程相同，只需更换“怎样合并两个数”。

cpp
template<bool Max>
__device__ float warp_reduce(float x) {
    for (int d = 16; d; d >>= 1) { // d非0时继续
        float y = __shfl_down_sync(0xffffffffu, x, d);
        if constexpr (Max) x = fmaxf(x, y);
        else x += y;
    }
    return x;
}
  • template<bool Max>：定义布尔型的编译时参数。调用时，warp_reduce<false>(x) 选求和，warp_reduce<true>(x) 选最大值。
  • if constexpr：编译时选择分支；true时用 fmaxf(x,y) 取两个float的较大值，false时相加。
  • block_reduce<false>(local) 把自己的 Max 设为false；内部的 warp_reduce<Max>(x) 继续传递这个选择，即调用求和版本。
17 · 主题链接

从 Warp 归约到 Block 归约

shuffle不能跨warp，因此这8个部分和仍用shared交接：各warp先求和 → 各写一个shared槽 → 同步 → warp 0合并这8项。下面是课程函数 block_reduce<false>(local) 的核心流程。

cpp
__shared__ float shared[8];
int lane = threadIdx.x % 32; // 在warp内的编号：0…31
int warp = threadIdx.x / 32; // 在block内的warp编号：0…7
float x = warp_reduce<false>(local);
if (lane == 0) shared[warp] = x;
__syncthreads();
if (warp == 0) {
    float v = lane < 8 ? shared[lane] : 0.0f;
    x = warp_reduce<false>(v); // 复用32项函数；16、8两轮只加0
    if (lane == 0) shared[0] = x;
}

% 取余数，整数 / 取商。例如线程37：37 = 1×32 + 5，所以属于warp 1，在其中是lane 5。线程0…31组成warp 0，32…63组成warp 1。

local 是线程部分和，x 是warp合并结果。第二轮仅有8项，其余lane填0；通用函数的16、8两轮只加0，专用8项版本可从 4、2、1 开始。

Block 归约的完整函数

把前页流程写成完整函数。template<bool Max> 在编译时选择求和（false）或最大值（true）：

cpp
template<bool Max> __device__ float block_reduce(float x) {
    __shared__ float shared[8];
    int lane = threadIdx.x % 32;
    int warp = threadIdx.x / 32;
    x=warp_reduce<Max>(x);
    if(lane==0) shared[warp]=x;
    __syncthreads();
    if(warp==0) {
        float v=lane<8 ? shared[lane] : (Max ? -CUDART_INF_F : 0.0f);
        v=warp_reduce<Max>(v); // 复用32项函数，前两轮可省
        if(lane==0) shared[0]=v;
    }
    __syncthreads();          // 等最终结果写好
    float result=shared[0];   // 各线程取同一个结果
    __syncthreads();          // 等大家读完再复用临时区
    return result;
}

无输入时，最大值归约填 -CUDART_INF_F（−∞），求和填0；返回时所有线程拿到同一结果。

设备归约的四个协作层级

课程原创图解 · 点击可查看矢量原图。

设第一阶段启动 G 个 block，只向 global memory 写 G 个部分和；第二阶段再归约这些部分和。两次 launch 放在同一 stream，无需回到 CPU 计算最终和。

设备范围归约不应依靠所有普通 block 同时到达某个自制 barrier。

20 · 主题链接

两阶段归约的工作规模

本讲选择 G = min(ceil(N/256), 256)；非空输入至少一块，每块256线程。

text
N=1,048,576：
256 blocks × 256 threads，每线程累计16项
    ↓ 每个block写一个部分和
256个部分和
    ↓ 第二个kernel：1 block × 256 threads
1个最终结果

第一阶段借助第五讲的 grid-stride 循环遍历全部 N。第二阶段继续在 GPU 上合并；中间无需把部分和下载给 CPU。

G=256 是本次实验配置，不是 GPU 的默认值或普遍最优值。两种归约版本采用同样的 G 和局部累加方式。

21 · 主题链接

两阶段归约的完整调用

cpp
__global__ void reduce_sum(const float* x, float* partial, size_t n) {
    float local = 0;
    for (size_t i = size_t(blockIdx.x)*256+threadIdx.x;
         i < n; i += size_t(gridDim.x)*256)
        local += x[i];
    float sum = block_reduce<false>(local);
    if (threadIdx.x == 0) partial[blockIdx.x] = sum;
}

dx.p 是N个输入，partial.p 有G个槽，out.p 有1个槽；非空输入时：

cpp
reduce_sum<<<G,256>>>(dx.p, partial.p, n);
reduce_sum<<<1,256>>>(partial.p, out.p, G);
CUDA_CHECK(cudaGetLastError());
CUDA_CHECK(cudaDeviceSynchronize());

同一默认stream保证先生成G个部分和，再合成最终结果；两次启动之间不用加CPU等待。shared树版本把两处函数名都换为 reduce_shared。

按行归约：实验输入与 shared 基线

比较每行各求一个和，对应 torch.sum(x, dim=1)。例如 [[1,2,3,4],[5,6,7,8]] → [10,26]。实验每行固定256项：一个block负责一行，一个线程读取一项。

cpp
__global__ void row_sum_shared(const float* x, float* out) {
    unsigned t = threadIdx.x;
    size_t row = blockIdx.x;
    __shared__ float s[256];
    s[t] = x[row*256+t];
    __syncthreads();
    for (unsigned d = 128; d > 0; d /= 2) {
        if (t < d) s[t] += s[t+d];
        __syncthreads();
    }
    if (t == 0) out[row] = s[0];
}

x 按行连续存放，out 每行一个结果。两版都用 <<<rows,256>>> 启动，读取相同输入；每行独立，不需要第二次kernel合并。

按行归约：shuffle 版本的完整 kernel

cpp
__global__ void row_sum_shuffle(const float* x, float* out) {
    unsigned t = threadIdx.x;
    unsigned lane = t % 32;
    unsigned warp = t / 32;
    size_t row = blockIdx.x;
    float v = warp_reduce<false>(x[row*256+t]);
    __shared__ float sums[8];
    if (lane == 0) sums[warp] = v;
    __syncthreads();
    if (warp == 0) {
        v = lane < 8 ? sums[lane] : 0.0f;
        for (int d = 4; d > 0; d /= 2)
            v += __shfl_down_sync(0xffffffffu, v, d);
        if (lane == 0) out[row] = v;
    }
}

第一轮各warp合并32项，第二轮只合并8项，从 4、2、1 开始。只有线程0写出行结果，因此无需全块广播，只保留一道block同步。

Block Scan：上扫与根节点清零

上扫每轮把两个半段相加：本段总量 = 左半段总量 + 右半段总量，写回右端 s[r]。d *= 2 让半段长度依次变为1、2、4……，覆盖范围逐轮扩大。

    unsigned r = (t + 1) * (2*d) - 1;
    if (r < 256) s[r] += s[r-d];
    __syncthreads();
}
if (t == 0) {
    total[blockIdx.x] = s[255]; // 保存本块总量
    s[255] = 0;               // 整块之前没有本块元素
}
__syncthreads();

Block Scan：下扫与输出

Block Scan 的完整 kernel

cpp
__global__ void scan_block(const unsigned* x, unsigned* out, unsigned* total, size_t n) {
    __shared__ unsigned s[256];
    unsigned t = threadIdx.x;
    size_t i = size_t(blockIdx.x)*256+t;
    s[t] = i < n ? x[i] : 0;             // ① 装入，尾部补0
    __syncthreads();
    for (unsigned d = 1; d < 256; d *= 2) { // ② 上扫，求各段总量
        unsigned r = (t+1)*2*d-1;
        if (r < 256) s[r] += s[r-d];
        __syncthreads();
    }
    if (t == 0) { total[blockIdx.x] = s[255]; s[255] = 0; } // ③ 保存总量，清根
    __syncthreads();
    for (unsigned d = 128; d > 0; d /= 2) { // ④ 下扫，传递前缀
        unsigned r = (t+1)*2*d-1;
        if (r < 256) {
            unsigned left = s[r-d];
            s[r-d] = s[r];
            s[r] += left;
        }
        __syncthreads();
    }
    if (i < n) out[i] = s[t];             // ⑤ 写出本块局部前缀
}

全局 Scan：把每块遗漏的总和加回来

以 1024个1 为输入，每块256项，一共4块。每块局部结果都是 [0,1,…,255]；totals=[256,256,256,256]，扫描后得到 offsets=[0,256,512,768]。

out 存放局部结果，offsets 每块一项。每个线程给自己的输出加上本块偏移：

cpp
__global__ void add_offsets(unsigned* out, const unsigned* offsets, size_t n) {
    size_t i = size_t(blockIdx.x)*256+threadIdx.x;
    if (i < n) out[i] += offsets[blockIdx.x];
}

例如block 2的线程37处理 i=2*256+37=549：局部结果是37，加上 offsets[2]=512，得到 out[549]=549。

每块的256个线程读取同一个偏移，各自更新一个输出位置。

全局 Scan：块总和仍然很多时怎么办

1024项只产生4个块总和，一个block能处理完。换成 1,048,576项，就会产生 4096个块总和；它们还要分16块扫描，再合并这16个总和。

每一层都做同样三步：本层局部scan → 下一层扫描本层totals → 本层加回offsets。当本层只需1个block时，局部scan就是这一层的完整结果，可以停止拆分。

把这些层需要的数组和调用过程组织起来，就是下面的 ScanPlan。

ScanPlan：保存每一层需要的数据

ScanPlan：run 如何连接相邻两层

run(x,out) 的参数是设备指针。每次调用，仍然执行前面展开过的三步：

cpp
void run(const unsigned* x, unsigned* out) {
    if (!n) return;
    scan_block<<<unsigned(blocks),256>>>(x, out, totals.p, n);
    CUDA_CHECK(cudaGetLastError());
    if (next) {
        next->run(totals.p, offsets.p);
        add_offsets<<<unsigned(blocks),256>>>(out, offsets.p, n);
        CUDA_CHECK(cudaGetLastError());
    }
}

关键是 next->run(totals.p, offsets.p)：本层的totals，成为下一层的输入；本层的offsets，成为下一层的输出。 ->run 表示通过指针调用成员函数。

最小层的 next 为空，跳过 if(next)；它提交一次block scan即可。所有层依次提交到同一stream，外层最后等待完成后再读取结果。

ScanPlan 的完整结构与使用

ScanPlan plan(n) 准备空间；plan.run(d_in,d_out) 提交计算；读取结果前用 cudaDeviceSynchronize() 等待。固定长度时可复用同一plan。

cpp
struct ScanPlan {
    size_t n, blocks;
    DeviceBuffer<unsigned> totals, offsets;
    std::unique_ptr<ScanPlan> next;
    explicit ScanPlan(size_t count)
        : n(count), blocks((n+255)/256),
          totals(blocks), offsets(blocks) {
        if (blocks > 1)
            next = std::make_unique<ScanPlan>(blocks);
    }
    void run(const unsigned* x, unsigned* out) {
        if (!n) return;
        scan_block<<<unsigned(blocks),256>>>(x, out, totals.p, n);
        CUDA_CHECK(cudaGetLastError());
        if (next) {
            next->run(totals.p, offsets.p);
            add_offsets<<<unsigned(blocks),256>>>(out, offsets.p, n);
            CUDA_CHECK(cudaGetLastError());
        }
    }
};

为什么大输入下 CUB Scan 更快

本讲分层实现先把局部结果写到显存，等块偏移算完，再把这些结果读回来、加偏移、写回。主数组多经过了一轮完整的读写。

实现主数组的逻辑读写块间偏移的处理
本讲分层scan局部scan读N、写N；加偏移再读N、写N，共约4N项分层求偏移，再单独加回
CUB DeviceScan读N项输入、写N项最终输出，约2N项用块状态传递前缀，在一遍扫描中写出最终结果

对 N=2²⁰、每项4字节，主数组分别约 16 MiB与8 MiB。本讲还需提交5个kernel；CUB减少了对主数组的分阶段处理，并对块内扫描方式、每线程处理项数等作了调优。

这些差异解释了大输入的优化方向。表中3.25×是完整实现的实测加速比；逻辑读写量不等于实际DRAM流量，也不能直接换算成耗时倍数。

N=8时，本讲只需一个block、一次kernel；数据量太小，库的状态初始化与调度等固定成本可能占主导，因此未必更快。

__global__ void mark_positive(const int* x, unsigned* flag, size_t n) {
    size_t i = size_t(blockIdx.x)*256+threadIdx.x;
    if (i < n) flag[i] = x[i] > 0 ? 1u : 0u;
}
cpp
__global__ void scatter_positive(const int* x, const unsigned* flag,
                                 const unsigned* pos, int* out, unsigned* count, size_t n) {
    size_t i = size_t(blockIdx.x)*256+threadIdx.x;
    if (i < n && flag[i]) out[pos[i]] = x[i];
    if (i == 0) *count = pos[n-1]+flag[n-1]; // Host only launches this for n>0.
}

条件 ? 1u : 0u 表示成立写1，否则写0；u表示unsigned常数。*count 写有效长度。例如输入的5位于 i=2，pos[2]=1，所以它被写到 out[1]。

scatter前，flag和pos已由前序kernel完整生成，因此线程0可以独立写有效长度。

稳定筛选：三个阶段的完整调用

cpp
// dx/out各n项；flag/pos各n项；count只有1项，均已分配。
ScanPlan plan(n); // 提前分配各层临时区
unsigned G = unsigned((n + 255) / 256);
if (n == 0) {
    count.zero();
} else {
    mark_positive<<<G,256>>>(dx.p, flag.p, n);
    plan.run(flag.p, pos.p);
    scatter_positive<<<G,256>>>(dx.p, flag.p, pos.p, out.p, count.p, n);
}
CUDA_CHECK(cudaGetLastError());
CUDA_CHECK(cudaDeviceSynchronize());

同一stream中依次完成 0/1标记 → 完整scan → 保序写出。最后CPU读取count，只消费out的前count项。

直方图：把输入变成各桶的计数

bin就是桶编号。先用4个桶，输入为 [1,0,1,3,1,0,2,1]：

桶编号0123
出现次数2411

每个输入执行一次“对应桶加1”。输入位置0和2都属于桶1，两线程若普通读改写，可能丢掉一次更新；atomicAdd 保证两次贡献都计入。

这就是block私有化：先各块数自己的，再把少量桶计数合起来。实际实验使用256个桶，输入值范围为0…255。

全局直方图：清零与原子累加

x 存n个桶编号，hist[256] 存各桶计数。例如 x[i]=1 时，该线程只需把 hist[1] 加1；多个线程可能同时给同一个桶加1。

cpp
__global__ void hist_global(const unsigned* x, unsigned* hist, size_t n) {
    for (size_t i = size_t(blockIdx.x)*256+threadIdx.x;
         i < n; i += size_t(gridDim.x)*256)
        atomicAdd(&hist[x[i]], 1u);
}
cpp
CUDA_CHECK(cudaMemset(d_hist, 0, 256*sizeof(unsigned)));
hist_global<<<G,256>>>(d_x, d_hist, n);

d_x 是n个桶编号；d_hist 是256个计数，事先分配。G沿用归约的grid设置，非空时每个block固定256线程。

x[i] 决定桶下标，&hist[x[i]] 是该桶的地址，1u 是加上的无符号整数1。

每次运行都先清零，同一stream保证清零在统计之前。cudaMemset 按字节填充，填0可以清计数；填1不表示把每个整数设为1。

Block 私有直方图的完整 kernel

hist[256] 是已清零的全局计数，local[256] 是本块计数。每线程 先清一个本地桶 → 处理分到的输入 → 再合并一个桶。

cpp
__global__ void hist_shared(const unsigned* x, unsigned* hist, size_t n) {
    __shared__ unsigned local[256];
    local[threadIdx.x] = 0;
    __syncthreads();
    for (size_t i = size_t(blockIdx.x)*256+threadIdx.x;
         i < n; i += size_t(gridDim.x)*256)
        atomicAdd(&local[x[i]], 1u);
    __syncthreads();
    unsigned v = local[threadIdx.x];
    if (v) atomicAdd(&hist[threadIdx.x], v);
}

回到4桶例：两块的局部计数 [1,2,0,1] + [1,2,1,0] = [2,4,1,1]。合并阶段，线程t读取 v=local[t]，把它加到全局桶t；if(v) 表示跳过0计数。

清零 → 同步 → 本块统计 → 同步 → 合并。 shared内部仍用atomicAdd处理同桶竞争；两道同步分别保护初始化完成与统计完成。

Gather、Scatter 与输出位置

课程原创图解 · 点击可查看矢量原图。

Gather：out[i] = in[index[i]]，通常每个线程拥有自己的 out[i]，但读取可能不连续。

Scatter：out[index[i]] = in[i]，必须知道 index 是否唯一。重复索引若要求和，就需要原子或分段归约；若要覆盖顺序，就必须显式定义与实现该顺序。

PyTorch 的索引读取与累加写入

python
import torch
x = torch.tensor([10, 20, 30, 40], device="cuda")
index = torch.tensor([2, 0, 2], device="cuda")
print(torch.index_select(x, 0, index).tolist())  # [30, 10, 30]
src = torch.tensor([1, 2, 3], device="cuda")
out = torch.zeros(4, dtype=torch.int64, device="cuda")
out.scatter_add_(0, index, src)
print(out.tolist())                            # [2, 0, 4, 0]

Gather 按索引读：依次读取 x 的第 2、0、2 项。Scatter-add 按索引加：把 src 的 1、2、3 分别加到 out 的第 2、0、2 项，故 out[2]=1+3=4。

参数 0 表示沿一维数组的第 0 维；scatter_add_ 末尾的 _ 表示直接修改 out。重复索引必须合并贡献，不能只保留某一次普通写入。

课堂运行：python .\07_pytorch.py gather。

基础算子的组合：Token 路由

对 top-1 expert 路由，可把第三讲的设计写成 GPU 阶段：

  1. Histogram：数每个 expert 收到多少 token。
  2. Exclusive scan：得到各 expert 输出段的起点。
  3. 分配组内位置并 scatter：把 token 放入对应连续段。
  4. 专家计算后，用保存的位置映射恢复原始顺序。

仅用原子分配组内序号时，组内通常不稳定；若模型流程需要确定顺序或可复现布局，要增加相应设计。top-k 还多出复制、权重合并和容量策略。

基础模式的价值，在于它们可以用清楚的边界组合成实际系统。

计数、scan和scatter依次成为设备端阶段；前缀完成后才可按位置写出。需要组内稳定顺序时，应显式计算rank。

通用库与专用实现的选择

优先使用库：通用 reduce / scan、复杂输入范围、跨设备与版本适配、维护成本重要。

值得研究专用 kernel：归约与上下游可以融合、行长固定或形状特殊、数据已经在寄存器/shared 中、标准接口迫使生成巨大中间数组。

专用实现的优势应该来自减少工作或搬运、利用明确的形状约束，并用库作为正确性和性能基线，而不是只比较最朴素的循环。
