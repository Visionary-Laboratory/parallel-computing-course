这些字段，比一个 GPU 名字更有意思

快照中的字段可以读出什么

05 · 主题链接

GPU-Util 相同，GPU 可能在做很不同的事

GPU-Util 统计执行 kernel 的时间占比，不统计算力用了几成。

假设 1 秒中有 0.86 秒至少一个 kernel 在执行，就对应约 86%。

理想化负载GPU-Util 与实际工作情况
少量线程持续运行接近 100%，很多计算资源仍空闲
大量读写、少量运算接近 100%，可能受访存限制
充分并行、复用良好的矩阵乘接近 100%，可能接近相应计算峰值
每轮算 2 ms，空闲 8 ms 等 CPU约 20%，但那 2 ms 内也可能很高效

高利用率不等于高吞吐。 本讲仍用结果校验和运行时间做比较。

数值为教学示意；采样窗口由设备决定，-l 1 只指定每秒刷新。指标定义。

A100、H200、B300 的名字怎么读

产品示例架构家族名称背后的人物
A100Ampere（安培）物理学家安培
H100、H200Hopper（霍珀）计算机科学家 Grace Hopper
B200、B300Blackwell；B300 属于 Blackwell Ultra数学家 David Blackwell

这几个数据中心产品的字母帮助识别架构家族。数字用于区分产品型号，具体升级了什么，要看相邻产品的规格：H100 → H200 是 Hopper 家族内的升级，H200 → B200 才换成 Blackwell 家族。

RTX 5090 Laptop GPU 是另一条产品线，必须保留 Laptop 后缀；桌面 RTX 5090 的规格不能套到笔记本。GB300 的 G 指向 Grace CPU 与 Blackwell GPU 的组合，不能与单颗 B300 或整套机柜混为一谈。

来源：A100 架构 · Hopper 命名 · Blackwell 命名 · Blackwell Ultra。

07 · 主题链接

从 100、200 到 300，究竟升级了什么

既有架构换代，也有同一家族内的升级。

产品变化升级重点
A100 → H100换成 Hopper；新增 FP8 与 Transformer Engine
H100 → H200仍是 Hopper；显存 80 → 141 GB，带宽 3.35 → 4.8 TB/s
H200 → B200换成 Blackwell；加强 FP4 计算与多卡互连
B200 → B300Blackwell Ultra；更大显存，更强 FP4 与注意力计算

H100/H200 按 SXM 版本比较：容量约 1.76 倍，带宽约 1.43 倍。B200/B300 的显存带宽上限则仍为 8 TB/s。

容量、带宽和计算吞吐可以分别升级。 哪种改进能让程序更快，要看程序的瓶颈；型号数字不能直接换算成加速比。

来源：Hopper 架构 · H100/H200/B200 对照 · Blackwell Ultra · HGX 产品规格。

计算能力 7.5，不是 7.5 TFLOPS

Compute Capability（CC，计算能力） 用“主版本.次版本”表示硬件支持的指令和功能。7.5 中 7 是主版本、5 是次版本；没有 FLOP/s 单位。

示例设备CC面向该架构的常见编译目标
T4 / RTX 20707.5sm_75
A1008.0sm_80
H100 / H2009.0sm_90
B200 / B30010.0 / 10.3sm_100 / sm_103
实验设备 RTX 5090 Laptop GPU12.0（实测）sm_120

12.0 大于 10.3，不能推出这台笔记本快于 B300。 CC 用于判断功能和编译兼容性；应用速度还取决于精度、执行单元、带宽、容量、功耗及工作负载。

来源：NVIDIA CC 对照表。表内架构目标须得到所用 Toolkit 支持；实验设备 12.8 能编译 sm_120，不表示它支持表中所有目标。

15 · 主题链接

区分 CPU 函数与 GPU 核函数

同一个 .cu 文件可以包含两种执行位置。 main() 在 CPU 上运行；带 __global__ 的函数是 GPU kernel（核函数）。

写法本讲中的调用与执行方式
普通函数，或 __host__ 函数CPU 调用，在 CPU 上执行；普通函数默认如此
__global__ void hello()CPU 用 <<<...>>> 启动，在 GPU 上执行，返回类型为 void
__device__ 函数GPU 代码调用的辅助函数，在 GPU 上执行
cpp
__global__ void hello() { printf("Hello from GPU!\n"); }
// 在 CPU 的 main() 中提交 GPU 工作：
hello<<<2, 4>>>();

上面是简化片段：先看执行位置，下一页拆解 <<<2, 4>>>。__global__ 函数体会由本次启动的每个线程分别执行。

16 · 主题链接

读懂 hello<<<2, 4>>>()

cpp
hello<<<2, 4>>>();  // 2 个 block，每块 4 个线程，无函数参数

一次启动的全部 block 组成一个 grid；每个 block 包含若干 thread。

部分在这个一维例子中的含义
hello要执行的 kernel 名称
<<<2, 4>>>启动 2 个 block，每个 block 有 4 个线程
()传给 hello 的参数；它没有形参，所以为空

因此一共 2 × 4 = 8 个线程，各执行一次函数体。若函数只打印一次，就会产生 8 条线程输出；这不保证 8 个线程同时执行或按顺序执行。

后面会写 add<<<blocks, threads>>>(d_a, d_b, d_c, n)：尖括号决定线程组织，圆括号传递数组地址和长度。

17 · 主题链接

每个线程怎样知道自己负责哪里

CUDA 在 GPU 代码中提供以下只读内建变量，无需自行声明。名称区分大小写，写作 blockIdx、threadIdx，其中 Idx 表示 index（索引）。

一维写法含义hello<<<2, 4>>>() 中的值
blockIdx.x当前 block 在 grid 中的编号0 或 1
threadIdx.x当前线程在所在 block 中的编号每个 block 内都是 0…3
blockDim.x每个 block 的线程数4
gridDim.xgrid 中的 block 数2

.x 取 x 方向分量；Dim 表示规模。编号从 0 开始，全局一维编号由我们计算：i = blockIdx.x * blockDim.x + threadIdx.x。

text
block 0：thread 0 1 2 3 → i = 0 1 2 3
block 1：thread 0 1 2 3 → i = 4 5 6 7
18 · 主题链接

把线程坐标打印出来，核对这 8 次执行

cpp
__global__ void hello() {
    printf("block=%u thread=%u blockDim=%u gridDim=%u global=%u\n",
           blockIdx.x, threadIdx.x, blockDim.x, gridDim.x,
           blockIdx.x * blockDim.x + threadIdx.x);
}
// main 中的核心步骤；完整源码还检查错误
hello<<<2, 4>>>();
cudaDeviceSynchronize();

例如 block=1 thread=2 blockDim=4 gridDim=2 global=6：第 1 号 block 的第 2 号线程，对应全局编号 6。

%u 打印无符号整数，\n 换行。CPU 调用 cudaDeviceSynchronize() 等待设备完成，设备端 printf 的缓冲输出在此可见。

8 条线程输出的 global 应覆盖 0…7，顺序可以不同；此外还有设备信息和 PASS。大量打印会干扰执行，这个程序只用于观察线程。

先把向量加法的契约写清楚

cpp
// CPU 参考定义；a、b、c 是长度为 n 的独立数组
for (size_t i = 0; i < n; ++i)
    c[i] = a[i] + b[i];

本例输入是有限 FP32 数；每个输出只依赖同位置的两个输入。输出与输入使用独立分配，n=0 返回空结果。

没有跨元素依赖，所以可以让不同线程拥有不同的输出位置。 后续增加共享数据之前，先保留这个简单的正确性理由。

从 main 出发，读完向量加法的五个步骤

在同一目录执行 code .\05_vector_add_demo.cu，打开**短版向量加法源码**，按其中的 1–5 号注释阅读：

  1. CPU 创建并填充输入数组 a、b，准备输出 c。
  2. 分配 GPU 数组 d_a、d_b、d_c，把数据上传。
  3. 启动 add，检查提交错误，并等待 GPU 完成。
  4. 下载输出到 c，在 CPU 上逐元素比较。
  5. 释放 GPU 数组，报告 PASS 或 FAIL。

main() 负责组织这五步；add() 只负责一个线程应算哪一项、怎么算。先看两者的接口，再逐步补齐数组与 API。

短版没有计时框架。后面的完整评测版另加预热、重复计时和统计；先把这个程序读懂、跑对。

Host 与 Device：传指针不等于传数据

cudaMalloc 把设备分配的地址写入一个 Host 端指针变量。Host 持有这个地址值，以便把它作为参数传给 kernel；这不意味着 CPU 可以直接解引用它。

本例中 a、b、c 是 CPU 数组，d_a、d_b、d_c 保存 GPU 数组地址。d_ 是我们选的命名前缀，编译器不会靠名字决定内存位置。

向量加法 kernel：每个线程写一项

cpp
__global__ void add(const float* a, const float* b,
                    float* c, size_t n) {
    size_t i = size_t(blockIdx.x) * blockDim.x + threadIdx.x;
    if (i < n) c[i] = a[i] + b[i];
}

每个线程执行同一份函数体，用自己的坐标计算 i。if (i < n) 保护真正的数组读写。

const float* a、const float* b 表示通过这些指针只读输入；float* c 指向可写输出，n 是元素个数。Host 传入 d_a, d_b, d_c, n，kernel 用形参 a, b, c, n 接收。

size_t 是表示大小和下标的无符号整数类型；size_t(blockIdx.x) 先转换再乘，避免乘法先在较窄类型中溢出。

CUDA_CHECK：把每次调用的错误检查写全

CUDA_CHECK 是课程定义的宏。下面是 common.cuh 中的实际实现（仅调整换行）：

inline void cuda_check(cudaError_t err, const char* expr,
                       const char* file, int line) {
    if (err != cudaSuccess) {
        std::fprintf(stderr, "%s:%d: %s: %s\n",
                     file, line, expr, cudaGetErrorString(err));
        std::exit(EXIT_FAILURE);
    }
}

错误检查：既检查提交，也检查完成

cpp
add<<<blocks, threads>>>(d_a, d_b, d_c, n);
CUDA_CHECK(cudaGetLastError());       // 检查 launch 等错误
CUDA_CHECK(cudaDeviceSynchronize());  // 等执行完成，检查执行错误

<<<...>>> 启动本身没有可交给 CUDA_CHECK 的返回码。cudaGetLastError() 读取并清除当前线程的 CUDA 错误状态；cudaDeviceSynchronize() 等待设备工作完成，并可能报告执行错误。

复习：Block 与 SM 的关系

回顾第二讲的 GPU 执行模型：普通 CUDA block 的线程在同一个 SM 上执行；同一 SM 可以容纳多个 block。

接下来查询设备参数时，用这几个已学关系解释“每块”“每个 SM”和“整个 grid”的区别。

  • 一个 grid 可以远大于 GPU 的同时驻留容量。
  • block 的运行顺序、与 SM 的对应关系不由 blockIdx 保证。
  • warp 是硬件组织线程执行的单位；block 是程序显式表达协作的单位。

正确的结果不能依赖“block 0 总先执行”或“这些 block 一定同时驻留”。

为什么用二维线程处理矩阵

一维也能处理矩阵。 对 3×5 矩阵，i=0…14 可以转换为 row=i/5、col=i%5。二维线程则让行、列的对应关系更直接：

cpp
// a 是 rows × cols 矩阵的行主序线性数组
size_t col = size_t(blockIdx.x) * blockDim.x + threadIdx.x;
size_t row = size_t(blockIdx.y) * blockDim.y + threadIdx.y;
if (row < rows && col < cols)
    out[row * cols + col] = 2.0f * a[row * cols + col];

dim3 是 CUDA 的三维规模类型。dim3 block(32, 8) 指定 (32,8,1)，共 256 个线程；未指定分量默认为 1。kernel<<<grid, block>>>(...) 分别指定 grid 各维块数与 block 各维线程数。

二维 (32,8) 与一维 256 的线程总数相同。二维不天然更快，但便于表达矩阵小块和邻域；两种方式仍用 row*cols+col 访问线性数组，每块线程总数仍受设备上限约束。

Grid-stride loop：一个线程可以处理多项

cpp
__global__ void add_stride(const float* a, const float* b,
                           float* c, size_t n) {
    size_t start = size_t(blockIdx.x) * blockDim.x + threadIdx.x;
    size_t step  = size_t(gridDim.x) * blockDim.x;
    for (size_t i = start; i < n; i += step)
        c[i] = a[i] + b[i];
}

start 是刚才的全局线程编号，step 是本次 grid 的总线程数；i += step 表示这个线程跳到自己的下一项。

例如 <<<2, 4>>>、N=19：编号 2 的线程处理 2、10、18，再加 8 得 26，因 i<n 不成立而退出。每轮相邻线程仍访问相邻元素。

每个合法下标都有唯一分解 i = q × step + start，因此不会漏算或重复写入。本讲限定数组规模，避免循环下标溢出。

cpp

CPU 基线是编译优化后的单线程 FP32 循环，允许自动 SIMD；并非整颗 CPU 的最优多核实现。Host 缓冲使用普通 pageable 内存。N=1003 的 CPU 时间接近计时分辨率，只看量级。

左图两轴为对数，线越低，耗时越短；右图误差线为 5 批平均调用时间的最小与最大值。
